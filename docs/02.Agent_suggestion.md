## 一、先接受哪些事实，哪些仍然是假设

当前比较稳妥的判断是：模型确实学到了一些可预测的行为规律；但相对简单的个人历史模型，Transformer 的优势随目标变化很大；将预测结果压缩为少量 surprise 特征后，给既有 XGBoost 的增量较小。

这不等于“序列表征无效”，也不能证明“只需加身份就能解决”。目前至少有四种可能同时存在：

1. 原有特征已经包含很强的对象、类别及历史行为信息，新特征较多是在重复这些信息。
2. 七个预测目标主要解释常见行为；解释常见行为的能力，不一定等于区分极少数正例的能力。
3. 将分布和隐状态压成五六个数，可能丢掉了上下文与组合信息。
4. 当前实验的生成特征口径、训练期重叠、早停和随机波动，仍使微小增益难以解释。

**务必区分早期 Seq2 和最后一轮 Hybrid。** 用户已经确认：最后一轮行为预测器使用了覆盖期内所有符合条件的事件锚点，输入同实体此前最多 16 个事件，训练 100 轮。不要再把早期 Seq2 的固定小锚点集限制套到最后一轮，也不要把“只选部分字段”误解成“只选少量事件”。100 轮反复使用同一覆盖期数据，并不等于获得了更多独立行为信息。

## 二、已有结果如何解读

### 2.1 三个阶段不能混为同一个实验

| 阶段 | 已知做法 | 能支持的结论 |
|---|---|---|
| Seq1 | 一阶条件概率、平滑和时间间隔离散化；比较冻结与扩展统计 | 简单序列统计值得作为强对照；某一种更新方式更复杂，不代表更好 |
| Seq2 | 小型 Transformer；固定训练锚点；输出偏离值与 16 维表征 | 行为预测改善，没有转化为当时验证集的 AP 改善 |
| 最新 Hybrid | 全覆盖期合法锚点；七头预测；按目标选简单模型或 Transformer；额外五或六列进入 XGBoost | 混合特征有小幅正向迹象，但还不能归因于 Transformer |

早期 Seq2 的验证 AP：控制组 0.052461；偏离特征组 0.051552；embedding 组 0.051620；全部新增特征组 0.050384。其结果提示“预测任务变好”和“下游任务变好”存在落差。不要据此直接判定最后一轮模型的 embedding 也无效，因为两次训练覆盖和模型产物不同。

最新结果如下。这里 AP 指原报告中的 AP；请核实实现为 `average_precision_score`，不要与梯形积分 PR-AUC 混用。

| 数据段 | Base40 / B4-t | Hybrid45 | Hybrid46 | Hybrid46 相对 Base40 |
|---|---:|---:|---:|---:|
| V | 0.050930 | 0.051104 | 0.051618 | 约 +1.35% |
| Test | 0.032183 | 0.032165 | 0.033347 | 约 +3.62% |
| OOT | 0.018979 | 0.018717 | 0.019482 | 约 +2.65% |

其中 Test 的绝对 AP 差为 0.001164。正向结果值得拆解，但尚没有足够的重复训练和配对不确定性估计来确认稳定增益。Hybrid45 在 Test、OOT 没有明显改善，Hybrid46 则更好，因此**第六列本身，以及它与其他列的交互，是最便宜、最应先验证的对象**。

不同时间段的 AP 下降不能仅凭这张表解释为模型退化；正例比例、样本难度和标签成熟度都可能变化。重点比较同一批样本上的模型差值。

### 2.2 七头预测结果的含义

以下为 P-select 上的平均 NLL，越低越好。对象对应原对象名称压缩字段，类别对应原类别字段。

| 预测目标 | 最佳简单预测器 | 简单预测器 NLL | Transformer NLL | 当前选用 |
|---|---|---:|---:|---|
| 对象 | B2 | 2.449898 | 2.821429 | B2 |
| 类别 | B2 | 2.595150 | 2.783994 | B2 |
| 渠道 | B2 | 0.244254 | 0.227074 | Transformer |
| 数值档位 | B2 | 1.655166 | 1.648756 | Transformer |
| 时间间隔 | B2 | 1.694074 | 1.640176 | Transformer |
| UTC 小时 | B3 | 2.730157 | 2.829273 | B3 |
| 星期 | B1 | 1.755500 | 1.745146 | Transformer |

已知简单模型：B0 是冻结的总体平滑分布；B1 是前一事件条件分布；B2 是最近 16 个个人历史事件的衰减分布，并用总体分布平滑；B3 是 B1、B2 和日历条件分布的固定混合。请复核实际权重、衰减单位、词表和未知类别处理。

对象、类别上，个人历史统计优于 Transformer；数值档位和星期上的神经模型优势很小。这说明不能只报告“七头中赢了几头”，而应同时报告差值大小、置信区间和按历史丰富程度的分组结果。

当前 Hybrid 并非“纯 Transformer 特征模型”：对象和类别来自 B2，时间组合中小时来自 B3，第六列也来自 B3。不能将 Hybrid46 的所有收益写成 Transformer 收益。

### 2.3 当前六列应复核为下面的口径

1. 对象 surprise：B2 对当前真实对象的负对数概率。
2. 类别 surprise：B2 对当前真实类别的负对数概率。
3. 数值 surprise：Transformer 对当前真实数值档位的负对数概率。
4. 渠道 surprise：Transformer 对当前真实渠道的负对数概率。
5. 时间 surprise：间隔、小时、星期分别求 NLL，除以冻结的对应 B0 熵，再对有效项取平均。
6. 小时偏离档：B3 预测小时的众数与实际 UTC 小时的圆周距离，分为 0、1、至少 2 档。

请确认第 5 列的有效项数量、零熵保护和缺失处理；第 6 列是否按类别处理。原始数值列与新增列不同的裁剪、填补策略应被记录，但不要为了“形式统一”未经验证就重做全套预处理。

## 三、原有强特征会不会限制新增特征发挥

更准确的说法是：**原有特征可能已经解释了新增特征携带的大部分有效信息。** XGBoost 不会因为某列“资历老”就阻止新列使用；但重复信息、有限树容量、列采样和正则化会影响收益分配。

因此：

- SHAP 或 importance 排名靠后，不能证明没有增量；排名靠前也不能证明有稳定增量。
- 去掉对象、类别后，新特征变得有效，只能证明它能替代部分信息，不能证明它能改善完整生产基线。
- 真正需要比较的是固定完整基线 F 后，`F + Z` 是否优于 F，其中 Z 为新表征。

可以做一个诊断性的 2×2 对照：完整 F、F+Z、去掉一组对象/类别历史特征的 F-minus、F-minus+Z。删除组必须事先定义，保留清单，不要反复挑选删哪些特征以制造增益。若只在 F-minus 上有效，结论是“替代性强、互补性弱”。完整 F 的结果始终是主结果。

## 四、下一轮先做低成本归因，不先重训 Transformer

### 第 0 步：产物和时间线核对

输出一页运行清单即可，不必重跑历史训练：

- 每个模型的配置、代码版本、checkpoint、预处理和词表版本。
- P-fit、P-select、监督训练 S、验证 V、Test、OOT 的真实起止；此前报告对 S 范围存在不一致，请以数据清单确认。
- 最新 Transformer 的层数、宽度、头数、参数量；不要沿用 Seq2 配置作为默认事实。
- 当前事件哪些已知字段进入输入，哪些只作为目标；确保没有把待预测字段或其等价变换作为输入，造成平凡预测。
- 每列特征的生成器版本、历史截止规则、缺失率、未知类别率。
- 监督采样代码的真实含义。已见报告更接近“每个正例配至多 50 个负例”，这与“每 50 个负例保留 1 个”完全不同；以代码确认，不做猜测。

**时间重叠的判断必须准确。** 若 P-fit 和 S 重叠，S 的 surprise 可能来自见过该事件、甚至见过其后事件的预测器，导致训练期特征偏乐观。无标签预训练与监督训练使用相同样本，并不自动等同于 Test 泄漏；但生成式误差特征尤其容易产生训练期和未来期的分布差异，加入身份参数后更应检查。

请同时记录两种时间约束：事件历史只读当前之前的数据；模型参数在何时训练和冻结。两者不是一回事。

### 第 1 步：复用现有特征，拆清楚第六列和简单统计贡献

为所有新对照加入同一组轻量覆盖信息 C：合法历史长度、是否零历史、距最近一次历史事件的时间、必要的目标有效性标记。已有同义特征直接复用，不重复添加。不能把“对象 surprise 缺失”直接当成“全新实体”。

推荐第一批只跑下列模型：

| 编号 | 输入 | 回答的问题 |
|---|---|---|
| R0 | 原始 F | 重现当前基线 |
| R1 | F + C | 原提升是否部分来自历史覆盖/缺失模式 |
| R2 | F + C + B3 小时偏离档 | 第六列单独是否足够解释主要提升 |
| R3 | F + C + 六列全简单模型版本 | 无需 Transformer 能达到多少 |
| R4 | F + C + 当前 Hybrid 六列 | 神经预测器相对简单模型究竟增加多少 |

R3 与 R4 保持列定义、分桶、平滑、缺失和归一化一致，仅替换概率预测器；R3 的各头选择仅根据 P-select 的无标签预测指标冻结。主要对比 R4−R3 和 R4−R2。已有 Hybrid45、46 作为背景结果，不必把所有组合都重跑。

先用一个种子筛查工程错误，再对有希望的固定方案用至少三个配对种子；每个种子所有模型使用相同监督样本及划分。第一批保持监督采样策略不变，以免将采样改变与新特征混为一谈。

### 第 2 步：仅选一个信息保留实验

若 R4 有线索或时间组合列明显过度压缩，再尝试以下两条中的一条，不同时铺开大网格：

**方案 A：把时间组合拆开。** 分别保留间隔、小时、星期 surprise，以及有效项数。这样 XGBoost 可以分别赋权，不必接受事先规定的平均。费用低，优先级高。

**方案 B：导出最新模型的历史隐状态。** 从同一个冻结模型取得预测前的历史表示，避免包含当前目标值。先用 16 或 32 维；若需 PCA，仅在允许的训练期拟合并冻结，同一个变换用于后续所有天。先试 `F+C+embedding`，再决定是否与 surprise 合并。Seq2 的 embedding 负结果应保留，但不等于最新模型必然如此。

另一种可备选的低成本输出是概率比：`log p_model(y|history) - log p_global(y)`，用于区分“总体罕见”和“对该实体罕见”；或者 `log p_T(y|history) - log p_B2(y|history)`，用于表示两类预测器的分歧。统一词表、平滑和概率下限后才可比较。这些分数有可能仍是冗余信息，不预设有效，也不要全量交叉尝试。

## 五、身份信息：值得试，但需要三个对照

### 5.1 为什么可能有效

没有显式身份输入，不等于没有个性化：最近 16 个同实体事件本身已经提供个人信息。身份 embedding 可能额外保存窗口外的稳定偏好，帮助区分“短历史相似、长期习惯不同”的实体。

但身份 embedding 是训练得到的一组参数，不会自动检索该实体的完整历史，也不会在冻结后自动学会新习惯。它可能改善熟悉实体的下一事件预测，却对新实体、低频实体和未来漂移帮助有限。实体 ID 也未必等价于真实用户 ID，不能未经验证合并多个实体。

### 5.2 公开工作的可迁移结论

NVIDIA 的公开示例明确包含身份字段，并将压缩后的隐向量加入树模型；其数据、原始基线和输出接口与本实验不同。PANTHER 结合身份/画像、历史及其他模块，下游同时使用画像表征和偏离信息。它们都不能证明“单独增加一个 ID embedding”就会改善这里的 AP。PANTHER 报告的主要线上提升口径也不是这里的 AP。[1][2]

### 5.3 推荐的小规模身份实验

先设严格时间顺序 `P0 → S0 → V0`：P0 学无标签预测器；冻结后生成 S0 特征并训练 XGBoost；V0 选方案。样本量以标签数量和可承受预算决定。可以只用较短月份范围，但不承诺任意几小时必然见效。先测一小段吞吐量，再确定训练预算。

同一 P0、同一锚点、同一优化预算，比较：

| 模式 | 预训练输入 | 检验的机制 |
|---|---|---|
| I0 | 最近 16 个事件 | 历史模型控制组 |
| I1 | 同样历史 + 稳定实体 ID embedding | 参数化身份记忆是否有用 |
| I2 | 同样历史 + 截止当时的长期行为摘要 | 有用的是身份，还是窗口外行为信息 |

I2 的摘要可为长期类别分布的低维表示、数值分位或平滑均值、活动强度和周期统计；只能读锚点之前的数据。先用手工少量摘要即可，不必新建复杂画像模型。另加一个便宜的下游对照 `F+C+这些摘要`，防止将摘要本身的收益误归因于 Transformer。

I1 实施建议：

- 使用 P0 内建立的身份词表；低频身份与新身份走 UNK；阈值在训练前固定。
- 从 8 或 16 维 ID embedding 开始，投影为一个 profile token，作为历史上下文输入。
- 可用小比例 ID dropout 降低身份依赖，但所有超参应事先固定，避免大网格。
- ID 按类别使用，不把编号当连续数值；不从 V0 扩展词表或更新 embedding 参数。
- 估算参数和优化器内存：身份数 × 维度只是参数数量；FP32 Adam 常还需要梯度和两个动量数组，粗略按每参数至少 16 字节估算，另加激活与框架开销。不能只算 embedding 文件大小。
- 若身份量使预算过大，固定一个可重现的实体子集做机制实验，并将该子集的可用历史读完整；结论只适用于该子集，不外推全体。

三种模式各自导出相同类型、相同维数的特征，接入同一个 S0 上重训的 XGBoost。不能拿缩短 S0 的新模型与原全量 Base40 直接比较来判断表征增益。

同时报告两层结果：

1. 预训练：总体及各组 NLL；已见身份、新身份、低频身份、高频身份。
2. 下游：各自完整基线上的 AP 增量，以及覆盖率、推理成本。

若 I1 仅改善 NLL 而没有 AP 增益，应明确结论为“身份帮助行为预测，尚未证明帮助下游排序”。若 I2 或直接摘要与 I1 相当，优先选择更便宜、更新机制更清楚的方式。

这里的“新身份”首先指 P0 未见、之后自然出现的实体。如果额外做严格实体留出泛化测试，必须从预训练数据和身份词表中一并排除对应实体，不要只在监督训练时排除。

## 六、评估规则：微小提升尤其需要同口径

### 6.1 主指标与选择过程

- 主指标固定为同一实现的 AP。Top 百分位曲线作为辅助展示，不要求每个阈值都严格优于基线。
- 尽量在完整自然比例评估集上算 AP。若必须抽样，使用已知包含概率和样本权重，明确这是估计值；不与自然比例结果直接混报。
- 记录标签成熟截止；不要将未确认样本一律解释为可靠负例。
- 早停使用的加权 `aucpr` 与完整集 AP 并非完全相同。最终候选应以固定验证 AP 选择，必要时定期离线计算候选 checkpoint 的 AP。
- 当前 Hybrid46 最佳树数接近训练预算上限；这意味着其早停是否充分仍不确定。给候选模型相同、足够完成早停的上限即可，不因此盲目扩大全部搜索。
- 无标签预测器选择用 P-select；下游特征和超参选择用开发验证集。Test、OOT 已经被查看，后续结果应标为探索性，最终确认保留新的时间段。

### 6.2 如何判断提升是否可信

三个配对训练种子衡量训练随机性；同一评估集上的配对重采样衡量评估样本的不确定性，两者不能互相替代。

建议先按连续日期块进行配对 bootstrap，在每次重采样中保留同一组样本对所有模型的预测，再计算 AP 差；日期块长度应考虑时间相关性，短窗口的区间可能很不稳定。可补充按实体聚类的重采样作为敏感性分析。不要把逐行独立 bootstrap 视为已经解决了重复实体和时间相关问题。

交付均值、标准差、AP 绝对差、相对差和置信区间；同时给出日期/周分段结果。不要将每日 AP 简单平均冒充整体 AP。

在看到新结果之前约定最小值得投入的增益 δ，并结合成本作判断。δ 由项目接受标准决定，不在本文随意规定。置信区间包含零时应写“证据不足”，不能写“已证明无效”。

## 七、按天 Parquet 的产物接口与 PIT 要求

新增产物仍按天保存，一条目标事件一行：

```text
event_id
event_time
generator_version
history_count
feature_1 ... feature_k
```

使用原始稳定事件主键左连接原特征表；不要用实体 ID 加日期连接，那会混合一天内的多个事件。若没有唯一主键，先确定稳定的上游行标识方案，不临时用可能重复的字段拼接。

所有统计和序列输入遵守“先查询、后更新”。同一时间戳事件若没有可靠先后顺序，应先对整个时间组生成特征，再更新状态。迟到事件应按实际可见时间处理，不能离线利用在线当时尚未收到的信息。

验收至少包括：输出行数、主键唯一性、连接命中率、缺失率、历史时间严格性、同一小样本重复生成一致性。禁止使用未来标签；预测器输入也不能偷偷加入预测时不可见的字段。

若不同时间段使用不同 encoder checkpoint，原始 embedding 坐标未必对齐，不要直接拼成同一列训练一个 XGBoost。首轮采用同一个冻结 encoder 最简单。概率、NLL 也要固定词表和归一化，避免版本变化造成分布跳变。

离线有收益后再验证在线实现：记录缓存更新时间、历史窗口、归一化常数、未知类别和缺失规则。对固定小样本逐列比较 Python 离线与在线实现；延迟报告应拆分状态读取、特征计算和模型推理，并给出尾延迟。无需在研究尚未见效时先建设完整线上服务。

## 八、执行顺序与停止条件

按下列顺序推进，不同时跑所有想法：

1. 核对运行清单和时间线，复现完整基线。
2. 完成 R0–R4，先判断 B3 第六列、覆盖信息和简单统计能否解释结果。
3. 只有存在待验证线索时，选择一次时间拆分或最新 embedding 实验。
4. 仍有合理动机且预算允许，再做 I0/I1/I2 小规模身份机制实验。
5. 固定方案之后，使用新的未来数据段确认；满足收益和成本要求再讨论部署。

若简单统计与混合模型相当，就保留简单方案。若表征只在删弱基线后有效，就记录替代能力，不宣称完整基线增益。若带身份模型只改善 NLL，就停止继续堆身份容量。若反复只有小且不稳定的 AP 差，先把结论写清楚，不默认再训练 100 轮。
