# 无标签序列表征增强 XGBoost 的两阶段实验

可以在当前项目已有的特征、按天 Parquet 数据和 XGBoost 基线上，实施两阶段增量实验。本文是可离线阅读的执行说明，文末链接只供追溯，不要求你联网、下载预训练权重或引入大型框架。

我们的核心假设是：**先从大量无标签事件学习行为规律，再把学到的数值特征交给已有的监督分类器，可能发现现有人工特征遗漏的信号。** 这是假设，必须用时间外测试验证，不能承诺改善。

第一阶段仅用 CPU，从最近数月的历史开始，尽快输出可加入 XGBoost 的少量特征；第二阶段再用一张可用 GPU，从头训练小型 Transformer。先完成第一阶段的数据闭环和结果，再扩展规模。请在现有工程旁新增实验目录，保留原模型与原始数据，不重写整个系统。

## 1. 先理解任务与边界

- 环境约 Python 3.12，CPU 4–48 核；外部依赖获取受限。
- 已有按天组织的原始事件、基础特征、标签，以及基线 XGBoost。
- 存在稳定的主体标识、关联对象标识，以及覆盖不完整、近期才较充分的可选上下文标识。
- 监督训练已做负例抽样。“50 倍负采样”含义必须从代码确认：是负例保留 1/50，还是采样后负正比为 50:1？记录实际概率，不自行解释。
- **无标签学习与状态回放使用抽样前的事件流。** 监督分类器仍使用原有的同一批抽样训练事件，以隔离新增特征的效果。
- 无标签阶段不要读标签。保留所有类别事件，不必为了排除极少数正例额外读取标签。未知标签也可用于学习行为；不能因此在监督训练中视为确定负例。
- 所有字段用通用映射配置。模型输入不得包含最终标签、事后结果、后补调查信息或目标决策之后才产生的字段。
- 第一版不依赖可选上下文标识。后续在其覆盖稳定的共同时间段单独做实验，不把“缺失”误解释为实体的新行为。

这封信不要求最新算法名次，而是把“无标签数据有用”这个方向转化为低成本、可证伪的实验。CPU 统计模型和聚类是成熟方法；Transformer 是后续更强的序列表示工具。

## 2. 第一项行动：检查现有项目，形成可执行配置

请先阅读已有训练、采样、时间切分、特征生成和评估代码；只读取获准的数据目录。输出一页诊断，至少包含：

1. 已安装的 numpy、pandas、pyarrow、scikit-learn、xgboost、torch 及可选 DuckDB/Polars 的版本；不要自动升级环境。
2. CPU、内存、磁盘余量、Parquet 压缩与分区方式、GPU 是否存在。
3. 基线训练/验证/测试范围、监督训练事件清单、抽样概率、现有指标。
4. 哪些输入在预测时刻已经可用，哪些历史字段会被修订；现有特征是否已经覆盖下文建议。
5. 稳定唯一事件键、时间精度、重复事件、乱序事件、实体历史长度分布。

如果一个必要字段缺失，先实现能够完成的分支，再提出具体问题。不要因为没有 GPU 或没有联网而停止 CPU 实验。

建议字段契约：

| 通用名 | 必需性 | 说明 |
|---|---|---|
| event_id | 必需 | 跨表唯一事件键；不可依赖文件行号进行跨表对齐 |
| entity_id | 必需 | 主体，用于连接历史序列；不直接作为学习目标 |
| event_time | 必需 | 事件发生时刻 |
| available_time / ingest_time | 优先 | 系统实际可见时刻；没有时必须记录 PIT 近似限制 |
| object_id | 可选但有价值 | 关联对象；高基数，不直接构建巨型转移矩阵 |
| category | 优先 | 稳定、低或中基数的事件类别 |
| value | 可选 | 当时可用的数值量；允许为负时使用 signed-log1p |
| channel / context_id | 可选 | 类别通道及覆盖不完整的上下文 |
| label / label_available_time | 仅监督阶段 | 目标与获知时刻，禁止混入无标签输入 |

没有 category 时，优先使用其他有意义的低基数字段。仍没有时，可用只在预训练期建立的 object 高频词表加 OTHER 回退；它只能作为弱基线，不能宣称恢复了对象语义。禁止用随机哈希桶作为下一事件预测目标来解释行为含义。

唯一键不存在时，必须与现有上游流水标识或确定性复合键核对。哈希所有字段并不自动解决重复事件，不能静默去重或静默一对多连接。

## 3. 共同时间协议：先避免制造虚假的增益

### 3.1 第一版采用四段时间划分

| 时间段 | 用途 |
|---|---|
| P：前约 6–8 周 | 拟合无标签统计、归一化、聚类或 Transformer；内部按时间留出尾部做预训练验证 |
| S：其后约 4–6 周 | 训练监督 XGBoost |
| V：其后约 1–2 周 | 选择阈值、早停及有限实验选型 |
| T：最后约 2–4 周 | 冻结配置后的最终时间外测试 |

范围是起始模板，按标签成熟度、正例数和数据可用性调整。稀有正例不足时扩大 V/T，而不是只测一天。监督训练和评估只能使用在对应模型训练/评估截止时已成熟、符合原有标签定义的数据。

P 的模型和编码词表必须在 S 开始前冻结。P、S、V 的过去事件都可以为后续事件构建历史状态，但不能用 V/T 更新表示模型参数、聚类中心、标准化参数或词表。测试期允许使用测试期内已经发生并可见的先前事件更新主体历史状态，这符合在线实际。

如现有基线使用另一套时间范围，保留其历史结果，但另建一个同 S/V/T、同训练事件、同测试事件的 A'。**新增特征模型必须与 A' 公平比较，不能拿不同时间段的旧分数直接比较。** 若能找到更早的 P 并完整覆盖原来的监督时间范围，则可复用原切分。

第一版不做复杂的滚动交叉拟合。后续需要覆盖更长监督训练期时，再设计多个过去窗口训练表示模型；不能把不同旋转坐标系的 embedding 直接拼在一起当作同一组特征。

### 3.2 每条事件必须“先输出，后更新”

```python
for event in events_in_visibility_order:
    history = state.get(event.entity_id)       # 只含当前事件之前可见的信息
    extra = make_features(event, history, frozen_artifacts)
    write(event.event_id, extra)
    state.update(event)                       # 不论它是否进入监督抽样，都更新
```

同一时刻若没有可靠的先后顺序，先对整组事件生成特征，再统一更新；event_id 排序只提供可重复性，不代表真实因果顺序。历史排序、迟到事件和可见性要复用线上语义。没有 available_time 时，以 event_time 回放只是近似，报告该限制。

晚到事件只在实际可见后进入状态。间隔等时序量要明确采用事件时间还是到达时间，出现负间隔不得静默修成合理值。历史修订也不得回填成过去已经知道的信息。

## 4. 实验一：CPU 学习无标签行为规律

按 1A → 接入 XGBoost → 1B 的顺序执行。1A 很轻，争取先给出两列特征；1B 才是更直接的无监督行为表示。两者都不读取标签。

### 4.1 实验 1A：平滑的一阶转移模型，输出两列“意外度”

直觉：对每个主体，把过去事件连起来，学习“某种事件后通常出现什么，以及通常间隔多久”。频次统计本身就是对概率模型参数的无标签估计，不只是手工设阈值。

在 P 上，按主体串联完整可用历史，累计：

- `N[a,b]`：上一类别为 a、当前类别为 b 的次数。
- `N_gap[a,g]`：上一类别为 a、到当前事件的间隔桶为 g 的次数。
- 对应的行总数与全局边际频次。

类别词表建议第一版最多 128–256 个有效类别，加 OTHER 与 MISSING，词表只由 P 确定。间隔桶可先使用固定边界，例如 10 秒、1 分钟、10 分钟、1 小时、6 小时、1 天、7 天、30 天。缺失及不可用间隔另设标记。用小时/天的实际单位生成，不使用人工类别编号的大小关系。

使用带全局分布回退的平滑概率：

```text
p_global(b) = (N_global[b] + beta) / (N_global_total + beta * K)
p(b | a) = (N[a,b] + alpha * p_global(b)) / (N_row[a] + alpha)
seq_category_surprise = -log(max(p(b | a), epsilon))
```

`beta=1, alpha=50, epsilon=1e-12` 可作明确的初始配置。间隔桶使用同样形式计算 `seq_gap_surprise`。若 a 从未出现，直接回退全局概率。不要因为转移未见过就输出无穷大。

这里是**上一类别条件下的间隔分布**，不是类别对条件下的间隔分布；先不增加稀疏性。历史不足时两列输出 NaN，并附带 `seq_history_count` 或至少 `seq_has_history`。XGBoost 中保持与原项目一致的缺失处理。

拟合后冻结统计表，在 S/V/T 中仅查询表、读取和更新主体上一事件状态。输出：

| 列名 | 含义 |
|---|---|
| cpu_seq_category_surprise | 当前类别相对上一类别的罕见程度 |
| cpu_seq_gap_surprise | 当前间隔相对上一类别的罕见程度 |
| seq_history_count | 可用历史事件数，或明确截断后的计数 |
| seq_has_history | 冷启动标记 |

当前事件的类别与已发生的间隔是预测时已知输入，允许用于计算；当前事件的事后结果不允许。

为何可能有用：监督抽样没选中的事件也参与统计，模型因此获得更稳定的行为背景；XGBoost 再学习“何种意外度在何种条件下与目标有关”。意外度高本身不等于正例。

为何可能无效：一阶类别顺序太粗、现有特征已覆盖、真实目标与这一规律无关。这一结果只否定这个特征方案，不否定全部自监督方法。

### 4.2 实验 1B：历史行为画像 + MiniBatchKMeans

目的：学习常见的历史行为类型，把每条事件发生前的主体画像表示为“距离不同典型行为有多远”。这是小规模、CPU 可训练的无监督表示。

先实现历史画像 `q_t`，完全由当前事件之前的状态生成，建议 16–32 维，优先复用已经可信的现有 PIT 特征：

- 最近 32 条可见事件中的类别比例：只选 P 的前 8–16 类，加 OTHER。
- 最近事件的 `log1p(gap)` 均值、标准差。
- 数值量的 signed-log1p 均值、标准差（字段存在时）。
- 最近 32 条中对象切换比例、不同对象占比。
- 小时的 sin/cos 均值、可用历史数。

有些信息可用固定时间窗替代，但必须记录定义；缺失的数值不能直接当 0，需配套可用性标记。比例分母是有效历史数，不能默认所有主体都有 32 条。

P 初期画像先经历历史积累。画像拟合可仅使用历史至少 4 条的样本，门槛写入配置；短历史主体在输出时回退 NaN 与覆盖标记。不能只保留高活跃主体而不报告覆盖偏差。

推荐处理顺序：

1. 在 P 完整事件流上生成并保存历史画像，或形成覆盖各日期的有界训练画像样本。所有可用事件贡献状态；不要求所有事件都成为聚类训练锚点。
2. 在 P 的画像上拟合缺失填充值及 `StandardScaler.partial_fit`；计数先 log1p，避免极端尺度支配距离。冻结 scaler。
3. 第二遍读取固定 scaler 转换后的画像，调用 `MiniBatchKMeans.partial_fit`。第一批必须至少包含 K 个有效样本；初始化用跨日期的有界样本，不只使用最初一天。
4. 初始 `K=8`、batch_size 4096–16384、固定随机种子。先一遍，需要时第二遍。初始化和批量 API 按本地 scikit-learn 版本实现，避免复制最新版本专有参数。
5. 冻结中心，对 S/V/T 的同一定义历史画像输出到 8 个中心的欧氏距离。

**禁止一边更新 scaler，一边用不断变化的坐标训练同一个聚类模型。** 不同批次坐标必须一致。聚类不应在 V/T 上重新拟合。

输出 `cpu_cluster_dist_00` 至 `cpu_cluster_dist_07`。如只想先试一两列，可输出最近距离 `d1` 和第二近距离与最近距离的差 `d2-d1`；这两列信息更少，建议与 8 列版本对照。不要把整数 cluster_id 当成连续数值解释。也不需要巨大的 one-hot 矩阵。

为何可能有用：同样的当前事件，在不同历史行为类型下可能含义不同；聚类距离把这些背景变成树模型可直接利用的数值特征。

必须做一个消融：先把画像 q_t 本身加入 A'，然后再加聚类距离。聚类若只改善 A'、却没有改善 A'+q_t，说明收益可能主要来自新增历史统计，而不是无监督压缩。

若 numpy/Parquet 可用但 scikit-learn 缺失，先完成 1A。不要自己实现复杂聚类库；列出最小依赖需求，同时交付已完成的两列特征与评估。

## 5. 大数据实现：几小时目标必须靠预算控制

“几小时见到结果”是首轮目标，不是对未知硬件、存储和现有 XGBoost 重训耗时的保证。先用 1 天或 2 天测量读取、排序、回放、写盘吞吐与峰值内存，再估算阶段时间。

### 5.1 数据不装进一个 DataFrame

- 只投影所需列；按 Parquet record batch 读取，建议先 64K–256K 行一批，根据内存调整。
- 不能假设按天分区就已经按主体和时间排好。
- 若现有数据已按主体分桶并有顺序，优先复用；否则用稳定哈希将 entity_id 分到 64/128 个桶，再分别按可见性语义排序。
- 不用 Python 内置 `hash()` 作为跨进程/跨运行分桶规则；用项目已有确定性哈希或标准库确定性方案，并保存算法版本。
- 桶内按主体、可见时间和可靠序号遍历，可一次处理一个主体，避免在 Python dict 内保存所有主体的 32 条对象记录。
- 如需外部排序，优先使用已有 DuckDB/Polars/Arrow 能力；没有时采用分块有序文件与归并。磁盘不足时缩小主体范围，不能退回全量 pandas 排序。
- 统计矩阵是固定小维度，每个桶局部计数、最后相加；不在每个事件上更新共享多进程字典。
- 并行度从 2–4 个工作进程开始；每个工作进程内部 BLAS/OMP 线程数设小，避免“48 进程 × 每进程 48 线程”。根据内存与磁盘吞吐逐步提高。
- 输出独立分片，末尾按天整理；避免多个进程同时写同一个 Parquet 文件和生成海量小文件。

事件按主体分桶不会损害单主体历史；本实验不构造完整跨主体图。以后做全局对象状态时不能直接把各桶的局部计数当作全局计数。

### 5.2 首轮规模选择

优先覆盖最近数月的 P/S/V/T，缩小列数和学习维度。如果全量回放超出预算，按 entity_id 稳定哈希选择约 1%–5% 主体，保留所选主体的完整历史，不逐行随机删掉其历史。扩大到足够的正例和类别覆盖后再评估。

如果模型只在主体子集上拟合，却对更广主体做推理，必须报告该拟合覆盖率。第一轮也可以只在这个主体子集内同时训练和评估 A' 与增强模型，但不得拿子集增强模型和原全体基线比较。

建议首轮给数据处理与 CPU 表示拟合设置 2–4 小时预算。超预算时按测得吞吐缩小主体范围，保留多个日期覆盖；记录实际耗时，不能声称“全量训练完成”。监督重训和全量评分另计。

实际脚本名可按现有工程习惯安排，但至少拆分：检查、拟合、特征生成、连接、重训、评估。不要只交付 notebook 截图。

每行输出必须包含：

```text
event_id
event_time
feature_asof_time
representation_version
seq_history_count
seq_has_history
cpu_seq_category_surprise
cpu_seq_gap_surprise
cpu_cluster_dist_00 ... cpu_cluster_dist_07

```

`feature_asof_time` 表示该行状态对应的可见性截点，不是文件生成时间。表示模型拟合截止时间另写 manifest，要求早于 S。特征值用 float32；时间戳精度与现有数据一致。NaN、缺失原因、编码规则写入 manifest。

连接方式：

```python
extra = read_extra_features(day, version)
base = read_existing_features(day)
joined = base.merge(extra, on="event_id", how="left", validate="one_to_one")
assert len(joined) == len(base)
```

这段是语义示例；大文件采用分桶/流式连接，不强制全日载入 pandas。若键实际是复合键，显式使用复合键。检查匹配率、重复键、NaN 比例、各时间段覆盖及与标签的关系。元数据列、时间字段和 event_id 不默认加入模型。

**已有 XGBoost 模型不能直接多塞几列继续预测。** 必须用扩展后的训练矩阵重新训练一个新模型，并保存新的特征顺序及模型版本。不要用新增列对旧模型做不受支持的继续训练。

第一轮保持 A' 与增强模型的训练事件、标签、抽样权重、随机种子、主要超参数及早停协议一致。第二轮若调优，每组给相同预算，调优只用 V。原始 A' 模型文件保留。

最小比较矩阵：

| 实验名 | 特征 |
|---|---|
| A' | 当前特征，公平时间范围内重训 |
| B0 | A' + 历史画像 q_t + 必要历史覆盖标记 |
| B1 | B0 + 两列转移意外度 |
| B2 | B1 + 聚类距离 |
| C | 当前最强 CPU 方案 + Transformer 特征 |

为快速交付，可先运行 A' 与 A'+两列意外度；正式判断时补齐 B0/B1/B2，区分人工特征与学习特征的贡献。第一轮不要同时改变负采样倍率、标签定义及时间切分。

## 7. 实验二：一张 GPU 上的小型自监督 Transformer

复用第一阶段的主体序列、时间协议、特征输出与评估。使用已安装且可用的 PyTorch，从随机初始化训练；不需要 Hugging Face、在线模型仓库或预训练权重。如果 torch 不可用，交付明确依赖与可执行代码，继续完成 CPU 实验，不宣称 GPU 部分已运行。

### 7.1 输入与起始模型

一个事件是一个 token；不要先转自然语言再分词。每个 token 将以下分量投影并相加或拼接后投影：

- category、channel 等少量低基数字段的 embedding。
- signed-log1p(value)、log1p(gap) 等数值与对应缺失标记。
- 小时/星期的周期编码。
- 位置编码。

第一版不把 entity_id 直接输入模型，避免记忆主体身份。object_id 先仅用于历史画像中的切换/新颖度等特征；后续有预算再试有界词表或稳定哈希输入，但不做巨型对象分类输出层。context_id 不进入第一版。

初始参数建议：

```text
history_length = 32         # 后续对照 64
d_model = 64
n_layers = 2
n_heads = 4
feedforward_dim = 128
dropout = 0.1
embedding_dim = 16
batch_size = 128            # 按显存调整，先 32/64 smoke test
optimizer = AdamW
learning_rate = 3e-4
weight_decay = 1e-2
gradient_clip_norm = 1.0
training_budget = 1–3 小时（首轮实验预算，不是完成保证）
```

参数量由实际词表决定，打印准确数值；目标是小模型，而不是套用一个庞大的现成 LLM。混合精度只在硬件与本地版本支持时启用。

### 7.2 训练目标：从历史预测下一事件

使用带因果 mask 的 TransformerEncoder 或等价自注意力模块，作用是只允许位置 i 看到不晚于 i 的输入。在序列内将位置 i 的输出用于预测位置 i+1 的类别和间隔桶；若存在 value，再预测下一数值的 signed-log1p。

```text
loss = CE(next_category)
     + 0.5 * CE(next_gap_bucket)
     + 0.2 * Huber(next_scaled_value)  # 无该字段则移除
```

这些权重只是起点。数值缩放只在 P 的训练部分拟合，分别记录各项 loss、类别频率基线和间隔频率基线。目标字段缺失时屏蔽对应 loss，PAD 位置不参与 loss。目标事件必须仍在 P 内，不允许用 S 的第一条作为 P 最后一条的训练目标。

严格检查输入/目标错位：预测当前事件时，不能把当前目标的类别或数值放进历史 token。训练样本可以含连续事件用于多个下一步预测，但必须有正确的因果 attention mask。

不要固定只取每个主体最后一个窗口。使用覆盖 P 各日期的锚点或不重叠/有限重叠窗口，限制高活跃主体占用的训练份额，并记录这一采样规则。锚点可抽样，锚点对应的历史上下文保持完整。

先生成约 10 万个窗口做端到端 smoke test，再根据实际窗口/秒扩展到约 50 万–200 万窗口或达到时间预算。数据加载采用有界缓存或预处理的连续数值数组，不在每个 GPU batch 内重新扫描 Parquet。

P 尾部留作自监督验证，选 checkpoint 后冻结；P 内预处理拟合也优先仅使用内部训练部分。验证无标签 loss 可用于选预训练模型，但不能代替后续 XGBoost 增益验证。

### 7.3 让 16 维输出真的受到训练

必须把压缩层放在预测头之前：

```text
history tokens
  → causal Transformer
  → 每个位置的 hidden state (64维)
  → Linear(64,16) + LayerNorm
  → category / gap / value prediction heads
```

这样 16 维表示直接受到各项训练目标约束。不能训练完后随手加一个未训练的随机 16 维层，就把它叫学到的 embedding。

对目标事件 t，取其之前最多 32 条可见历史，选择最后一个有效历史位置的 16 维输出作为 `ssl_emb_00...15`。右侧 padding 时按有效长度取最后位置，不能一律取 `[:, -1]`；同时正确设置 padding mask。没有历史时不送入全 padding attention，直接输出约定缺失值及标记。

还可输出 `ssl_category_surprise` 和 `ssl_gap_surprise`：用历史预测分布与当前已知类别/间隔计算负对数概率。它们允许使用当前事件作为评分对象，但当前目标不得进入预测它的历史输入。

为何可能优于实验一：一阶转移只看上一类别；Transformer 可以同时利用较长历史中的顺序、间隔、数值变化及组合。它学习的是可预测的行为结构，XGBoost 再决定这些结构与监督目标如何关联。

### 7.4 生成特征与上线边界

S/V/T 采用同一个冻结 checkpoint、同一词表与同一数值缩放。分批离线推理，写成同一套按天 Parquet，再按 event_id 接入 XGBoost。训练和推理都固定历史截断规则；第一版直接按长度 32 的滑窗推理，不实现复杂 KV cache。

先完成离线增益验证，再测服务化。如果未来打算异步缓存 embedding，则必须在离线回放中模拟真实缓存刷新频率、事件可见性、embedding 年龄和冷启动，重新评估；不能用每条事件精确更新的离线效果代表周期缓存效果。

如果只有新输出没有效果提升，依次检查：历史长度覆盖、字段信息、目标是否只学会高频类别、mask、目标错位、训练预算，以及现有特征是否已覆盖。不要第一反应扩大层数。

## 8. 如何判断有效：稀有正例下的固定评估协议

优先使用未做负采样且标签成熟的 V/T。成本受限时仍优先保留完整 T，用批量评分控制内存；若测试也抽样，必须记录抽样概率，并计算加权混淆矩阵、precision、AP 等，不能把抽样分布下的 precision 当生产值。

至少报告：

- AP（明确使用 average precision 的定义，不与梯形 PR-AUC 混称）。
- 原系统实际低 FPR 区间的 recall；初始可展示 0.01%、0.05%、0.1%，再按业务目标调整，不能只看 1%–5%。
- 固定告警数量或固定告警比例下的 precision/recall。
- 每日表现与整个 T 的汇总；正例数、主体数及历史覆盖率。
- CPU/GPU 拟合、特征生成、连接、监督重训和评分的分项耗时与内存。

两种比较分开报告：

1. T 上的 recall@FPR 曲线用于描述排序能力，可以按各模型曲线取点，但这不是可部署阈值。
2. 在 V 上选阈值并冻结，在 T 上报告实际 FPR、recall 和告警量，反映真实部署表现。

检查极低 FPR 的统计支持：例如只有一万个负例时，0.01% FPR 仅对应一个误报，估计很不稳定。优先扩大负例评估覆盖，并给出计数，不能只报四位小数。

首轮可同一随机种子快速筛选；有信号后，用多个种子及按天或主体成组的配对 bootstrap 检查稳定性。不要把同一主体的高度相关事件视作大量独立证据。保存每个事件的 A'/增强模型预测，以便配对比较。

负采样会改变输出概率的解释。首轮保持现有权重和采样方案，不额外叠加新的类别权重；如需要概率校准，使用自然分布或有正确权重的 V 单独做，不能一边改变校准、一边把收益全部归给新特征。

有用的结果可以是：固定误报成本下稳定提高召回、固定处理量下提高命中、部分稀缺历史人群稳定改善。若只 AP 上升而目标低 FPR 下无改善，也要如实报告。

## 9. 必须通过的少量正确性检查

这些检查针对具体泄漏风险，不要求建设大型测试平台：

1. 手造两个主体各几条事件，逐条验证“先输出、后更新”、首次事件缺失及转移概率。
2. 将某时刻之后的事件修改或删除，之前已生成的特征必须保持不变。测试同时覆盖未来同主体事件。
3. 同一历史跨两个日期分区切开，结果与连续输入一致。
4. 同时间戳无可靠顺序时，批次排列变化不改变这组事件的历史特征。
5. 打乱 labels 后，无标签统计、聚类与 encoder 输入完全不变；训练脚本不能依赖标签列。
6. 连接前后事件行数一致、唯一键无重复，S/V/T 使用同一表示版本。
7. Transformer 改变未来 token 时，过去位置输出不变；PAD 不参与 loss，16 维层确实获得梯度。

## 11. 研究依据与离线阅读要点

以下是通用方法的公开依据，核查日期为 2026-10-17。本文没有把 CPU 转移模型或 KMeans 宣称为最新研究；它们用于低成本验证。论文不保证在本项目有效，核心证据必须来自上面的时间外对照。

1. **VIME，NeurIPS 2020**：通过遮蔽恢复等自监督目标从无标签表格学习，支持“先学表示，再做监督任务”的思路；本文 Transformer 采用下一事件预测，并非复现 VIME。
   https://papers.nips.cc/paper_files/paper/2020/hash/7d97667a3e056acab9aaf653807b4a03-Abstract.html
2. **SCARF，ICLR 2022**：通过随机特征扰动做表格对比学习，研究无标签预训练、标签噪声与低标签覆盖；随机扰动可能破坏时序语义，所以第一版不直接套用。
   https://arxiv.org/abs/2106.15147
3. **TabArena，2025**：强调可靠基准、调参预算及模型集成；树模型仍是强基线，表示学习必须证明相对它的增量收益。
   https://arxiv.org/abs/2506.16791
4. **MiniBatchKMeans 官方文档**：说明小批量聚类与增量接口。以企业已安装版本为准。
   https://scikit-learn.org/stable/modules/generated/sklearn.cluster.MiniBatchKMeans.html
5. **StandardScaler 官方文档**：支持分批拟合；拟合与聚类训练应在固定坐标下分阶段进行。
   https://scikit-learn.org/stable/modules/generated/sklearn.preprocessing.StandardScaler.html
6. **PyTorch TransformerEncoderLayer 官方文档**：提供从头构建小型注意力模型的基础模块。本文补充的因果 mask、padding、目标错位处理仍需自己明确实现和检查。
   https://docs.pytorch.org/docs/stable/generated/torch.nn.TransformerEncoderLayer.html

请先从 CPU 的两列意外度开始，把真实数据、PIT、每天特征文件和现有 XGBoost 连起来。第一份交付应是可复现的比较结果，而不是更大的模型设想。
